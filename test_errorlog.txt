ERR-001 | 2026-02-25 | SyntaxError: orphan except
================================================================================
FILE:     app/manufacturing/extractors/vlm_client.py (line ~245)
SYMPTOM:  SyntaxError: invalid syntax — "Expected expression" at `except Exception as e:`
          Variable `e` reported as not defined.

WHAT HAPPENED:
  A new `try/except` block was added inside `analyze_image()`. The `except:` was
  written correctly, but the matching `try:` was accidentally omitted. Result:

      for image in images:
          base64_images.append(...)
                                      ← blank line, for-loop ends here visually
          effective_prompt = prompt   ← this looks indented inside for, but
          ...                           Python sees it OUTSIDE any try block
          return content
      except Exception as e:          ← orphan except → SyntaxError

  Python flags the `except` line because there is no `try:` at the same scope.
  The variable `e` "not defined" is a secondary symptom of the same parse failure.

ROOT CAUSE PATTERN:
  "Added one side of a try/except pair and forgot the other side."

FIX:
  Inserted `        try:` (8 spaces) on the blank line before `effective_prompt`.
  The inner block indentation (12 spaces) was already correct for a try-body.

PREVENTION:
  1. After writing any `except:`, immediately scroll up and confirm a matching
     `try:` exists at the same indentation level in the same function scope.
  2. Run ast.parse IMMEDIATELY after saving — SyntaxError surfaces here:
       python -c "import ast; ast.parse(open('app/manufacturing/extractors/vlm_client.py', encoding='utf-8').read()); print('OK')"
  3. Use lsp_diagnostics after every edit — orphan except shows as
     "Expected expression" and the except-variable shows as undefined.

ERR-002 | 2026-02-13 | StreamlitAPIException: default value not in options
================================================================================
FILE:     aov_app.py — 知識庫管理 Tab (line ~1011)
SYMPTOM:  StreamlitAPIException: The default value 'I01' is not part of the options.
          Please make sure that every default value also exists in the options.
REPEAT:   發生過 5 次以上（每次重構知識庫管理頁面時重複犯錯）

WHAT HAPPENED:
  The knowledge-base management tab uses `st.multiselect(options=all_process_ids,
  default=entry['correct_processes'])`. `all_process_ids` was built from:

      pipeline = st.session_state.mfg_pipeline
      if pipeline is not None:
          all_process_ids = list(pipeline.decision_engine.processes.keys())
      else:
          all_process_ids = []    ← THE BUG

  `mfg_pipeline` is only initialized when the user clicks "開始辨識製程".
  If the user opens the app and immediately switches to the 知識庫管理 Tab
  (before running any recognition), pipeline is None → all_process_ids = [] →
  any stored process ID like 'I01' is not in options → crash.

ROOT CAUSE PATTERN:
  "Assumed a session-state object is always initialized; it only initializes
   on first user action, not on app startup."

FIX:
  Added a JSON fallback when pipeline is None:

      else:
          try:
              with open('app/manufacturing/process_lib_v2.json', encoding='utf-8') as f:
                  data = json.load(f)
                  all_process_ids = list(data.get('processes', {}).keys())
          except Exception as e:
              st.error(f"無法載入製程清單: {e}")
              all_process_ids = []

PREVENTION:
  1. Every `st.session_state.mfg_pipeline` access must have a None-guard + fallback.
     There is NO guarantee pipeline is initialized when any Tab is opened.
  2. Whenever writing `st.multiselect(default=X, options=Y)`:
     assert all(v in Y for v in X), "default values must be a subset of options"
     or filter: default=[v for v in X if v in set(Y)]
  3. Startup-safe process ID retrieval helper (use this everywhere):

       def _get_all_process_ids() -> list:
           pipeline = st.session_state.get('mfg_pipeline')
           if pipeline is not None:
               return list(pipeline.decision_engine.processes.keys())
           try:
               import json
               with open('app/manufacturing/process_lib_v2.json', encoding='utf-8') as f:
                   return list(json.load(f).get('processes', {}).keys())
           except Exception:
               return []

  4. Test this by: opening the app → going straight to 知識庫管理 Tab
     (do NOT click 開始辨識 first). If no crash → prevention confirmed.

ERR-003 | 2026-02-25 | NameError: name 'Dict' is not defined
================================================================================
FILE:     app/manufacturing/extractors/vlm_client.py (line 314)
SYMPTOM:  NameError: name 'Dict' is not defined
          Raised at module-level on `def analyze_engineering_drawing(...) -> Optional[Dict[str, Any]]:`
          App crashes immediately on startup — every import of vlm_client fails.

TRACEBACK (same path every time this module fails):
  aov_app.py:26
  → app/manufacturing/__init__.py:31
  → app/manufacturing/pipeline.py:30
  → app/manufacturing/extractors/parent_parser.py:20
  → app/manufacturing/extractors/vlm_client.py:314

WHAT HAPPENED:
  The file had a duplicate import block (copy-paste artefact from earlier work):

      # Block A (line 13) — survived
      from typing import Optional, Union, List

      # Block B (lines 19-23) — was the "duplicate" that got deleted
      import json       ← forbidden, correctly targeted for removal
      import re         ← forbidden, correctly targeted for removal
      from pathlib import Path
      import numpy as np
      import cv2

  The cleanup pass deleted ALL of Block B to remove json and re.
  Block A only had `Optional, Union, List` — `Dict` and `Any` came from
  somewhere else in the original file and were lost in the cleanup.
  The module-level function at line 314 still referenced `Dict[str, Any]`
  → NameError on every import.

ROOT CAUSE PATTERN:
  "Deleted a whole import block to remove 2 names; silently dropped other
   names that were also needed. ast.parse() passed because it's a valid
   annotation syntax — the missing names only surface at runtime import."

FIX:
  Line 13: from typing import Optional, Union, List, Dict, Any
  Commit: 17a1fe0

PREVENTION:
  1. UNION BEFORE DELETE rule:
     When removing duplicate import blocks, collect ALL names from every
     duplicate `from X import ...` line, merge into one line, then delete
     the originals. Never delete a block until you have the merged line ready.

  2. ast.parse() is NOT enough after import cleanup.
     It only validates syntax. NameError requires a real import:
       python -c "from app.manufacturing.extractors.vlm_client import VLMClient; print('OK')"

  3. Run flake8 F821 (undefined names) after every import-related edit:
       python -m flake8 app/manufacturing/extractors/vlm_client.py --select=F821
     This would have caught `Dict` and `Any` as undefined.

  4. When the task is "remove `import json`", do a SURGICAL edit:
     Change: `from typing import Optional, Union, List, Dict, Any`  (keep)
     Delete: only the line `import json`
     Never touch other lines in the same block.

  5. Post-cleanup verification sequence (run all three):
       Step 1 — syntax:  python -c "import ast; ast.parse(open('vlm_client.py', encoding='utf-8').read()); print('syntax OK')"
       Step 2 — import:  python -c "from app.manufacturing.extractors.vlm_client import VLMClient; print('import OK')"
       Step 3 — flake8:  python -m flake8 app/manufacturing/extractors/vlm_client.py --select=F821

PATTERNS — 這個 codebase 的高頻錯誤規律
================================================================================

PATTERN A: Session State 初始化假設
  ┌─ 症狀: Streamlit UI 在某些 Tab / 路徑下崩潰
  ├─ 原因: 假設 `st.session_state.X` 一定已存在
  └─ 規則: 所有 session state 存取必須用 `.get()` 或明確 None-guard + fallback

PATTERN B: Import 清理時名稱遺失
  ┌─ 症狀: NameError at module-level, 但 ast.parse 沒報錯
  ├─ 原因: 刪除 import 行時連帶刪掉其他仍在使用的名稱
  └─ 規則: UNION → MERGE → DELETE，事後跑 flake8 F821 + 實際 import 測試

PATTERN C: try/except 只寫一半
  ┌─ 症狀: SyntaxError "Expected expression" at `except`, 且 `e` undefined
  ├─ 原因: 加 except 忘加 try（或反之）
  └─ 規則: 寫 except 後立刻往上確認同層的 try，再跑 ast.parse

PATTERN D: VLM JSON 殘留
  ┌─ 症狀: VLM 輸出包含 `{}` 或 json.loads 拋出 JSONDecodeError
  ├─ 原因: 舊的 response_format="json" 或 get_default_prompt 未清除
  └─ 規則: forbidden 掃描（見下方命令）後才能提交

FORBIDDEN PATTERN SCAN（每次提交前）：
  python -c "
  import re, os
  bad = [r'json\.loads\(', r'response_format=[\'\"](json)[\'\"]]']
  files = ['aov_app.py','app/manufacturing/pipeline.py',
           'app/manufacturing/extractors/vlm_client.py',
           'app/manufacturing/prompts.py']
  ok = True

          if hits: print(f'VIOLATION {f}:{hits}'); ok = False
  print('ALL CLEAR' if ok else 'FIX BEFORE COMMIT')
  "
