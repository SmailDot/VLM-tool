## 系統分工與責任邊界

### Step 1：Visual Observer（觀察者，1 call）

**核心角色定位**
- 是工程圖面的**純被動描述者**，不是製程分類器
- 唯一目標是「說出看到什麼」，禁止「猜測做什麼」

**輸入**
| 項目 | 說明 |
|------|------|
| 父圖 | 工程圖正本（PDF轉影像，通常單頁，200 DPI） |
| 子視圖 | 3～4張投影圖（正面、俯視、側面、等角圖），JPG格式 |
| 全部同時送入 | 不分批，一次性完整輸入 |

**5段結構化輸出**
```
1. 材料/表面標註（10～30字）
   • 材質文字標識（如「SUS304」「鋁」「塑膠」）
   • 表面符號（如毛面、拋光符號）
   • 塗裝色號（如「RAL 9003」）
   • 防烤/遮蔽標記（如「不烤漆此面」）

2. 幾何特徵（30～60字）
   • 折彎線及折彎數量、位置
   • 孔位分布、螺紋孔（M3/M4/M5）
   • 沉頭孔、沉台、螺紋深度
   • 切口、開口、邊界形狀
   • 圓管、U形、T形、L形等特殊形狀

3. 焊接/接合特徵（20～40字）
   • 焊接符號（標準銲接符號位置與類型）
   • 點焊標記、焊接點數量
   • 鉚合符號、點焊螺帽/螺柱
   • 組立關係（如「此為上蓋」「此為底座」）

4. 文字標註與備註（30～50字）
   • 所有中英文備註、特殊加工指示
   • 公差要求（如「±0.5」）
   • 客戶規格文字、特殊要求
   • 生產特殊需求備註

5. 整體判斷（20～40字）
   • 零件類型：單件鈑金 / 組合件 / 管件 / 其他
   • 複雜度等級：簡單 / 中等 / 複雜
   • 初步工序預感（不命名製程，只說「涉及多工序」等）
```

**防幻覺規則**
- 若特徵模糊或不確定，強制寫「疑似[特徵]，待確認」
- 絕對禁止發明圖面上看不到的內容
- 模糊距離、數值時用「約」「大約」等限定詞

**輸出示例**
```
【材料/表面標註】
圖面標示「SUS304」，無特殊表面處理標記，未見烤漆色號。

【幾何特徵】
側視圖、等角圖顯示有1處90°折彎（左上角），俯視圖可見3個圓孔（孔徑不同），
其中兩個角上有沉台設計。

【焊接/接合特徵】
焊接符號標記於三處：底部邊線（連續焊）及兩個角落（點焊或短焊）。
無點焊螺帽標記。

【文字標註與備託】
備註：「焊後檢測漏水」「須鈍化處理」，公差標示±0.5。

【整體判斷】
單件鈑金組件，涉及切割、折彎、焊接、清潔等多工序。複雜度中等。
```

**輸出限制**
- 字數：150～250 字（強制控制）
- 語言：繁體中文
- 結構：必須按 1～5 段順序，不可跳段或重排

### Step 2：8 個並行分類 Agent（8 calls，無序並行執行）

**通用架構**
- 每個 Agent 接收**完全相同的輸入**：Step1 輸出 + 原始工程圖面 + 業務上下文
- 各 Agent 相互獨立，無信息流，只看自己的製程代碼範圍
- 全部並行執行（ThreadPool），無等待依賴

**通用輸入**
```
Step1_output：自然語言描述 + 圖面參照

工程圖面：
  • 父圖（PDF轉影像）
  • 子視圖 × 3~4 張（正、俯、側、等角）

上下文（可選）：
  • BOM 資訊（若提供）
  • 客戶需求備註
  • 特殊工藝需求
```

**通用輸出格式**
```
[製程編號] [製程名稱] | [0.00] | 依據：[具體觀察到的圖面特徵或文字]
※ 人工加註項目加尾標：「⚠️ 人工加註，待業務/現場確認」
```

**通用信心度評分標準**
| 分數段 | 意義 | 例子 |
|--------|------|------|
| 0.90~1.00 | 圖面明確可見，文字/符號精確吻合 | 焊接符號標準、「M3 螺紋孔」清晰標示 |
| 0.70~0.85 | 幾何或材料強烈暗示，無直接標示 | 厚板 + 沉台孔 → 需銑削（暗示K01燕巢） |
| 0.50~0.65 | 合理推測，基於零件複雜度或工序邏輯 | 鈑金件 + 孔位 → 可能需二次檢 |
| 0.30~0.45 | 間接推測，僅憑旁證 | 白鐵材質 + 焊接 → 可能需鈍化（弱暗示） |
| 0.10~0.25 | 極低可能，僅供人工複核 | 無明確標記但邏輯上不太可能 |

**強制規則：禁止輸出整數分數（0.5、0.7、0.9），必須強制精確區分（0.55 vs 0.65 體現不同的判斷邏輯）**

**通用多視角規則**
- 任意**單一視角**看到特徵即可觸發該製程（不需全部視角一致）
- 若不同視角有矛盾，以最清晰、最詳細的視角為準
- 若圖面描述衝突，**圖面永遠優先於 Step1 文字**

**通用去重與互斥規則** — 見下表

**§1 合併規則**
```

score 0.50~0.69

  → 僅當業務規則強制觸發時納入
```

**§2 信心度重算**
```
base = 各 Agent 報告的最高分

correction:
  +0.05 if 證據同時出現在「圖面影像」+「Step1文字描述」
         （雙重確認，增強信心）
  -0.05 if 證據僅在「Step1文字描述」無圖面影像確認
         （削弱信心，描述可能遺漏視角）

final score = max(0.10, min(1.00, base + correction))
            = 四捨五入至2位小數
```

```
⚠️ 人工加註項目需業務或現場確認後方可加入製程。
```

## 系統核心邏輯總結

### 互斥 vs 依賴

| 規則類型 | 行為 | 輸出結果 | 例子 |
|---------|------|--------|------|
| **互斥** | 兩個製程衝突，只能一個 APPLY | 只輸出被選中的那個 | C01 vs C05，D01 vs D04 |
| **依賴** | B 自動觸發當 A APPLY | 兩個都輸出（並存） | F01 焊接 → F14 焊接研磨 |

### 信心度分層

| 分層 | 分數 | 處理方式 | 典型應用 |
|------|------|--------|---------|
| 高信心 | ≥0.70 | 無條件納入主表 | 圖面明確標示 |
| 中信心 | 0.50~0.69 | 納入（除非有矛盾） | 幾何強烈暗示 |
| 推測 | 0.30~0.49 | 僅業務規則強制 | 間接線索 |
| 低信心 | <0.30 | 移至待人工確認 | 極低可能 |

### 人工項目處理

所有帶 ⚠️ 標記的項目：
- **永遠不自動納入**，無論分數多高
- **必移至「待人工確認」表**
- 需業務 or 現場人工確認後才加入流程
- 典型項：F10(植焊螺絲)、F16(自動焊接)、O04(廠驗)、I14(進料檢驗)

```
│                       #   • 封裝 API 呼叫
│                       #   • 處理圖面影像編碼（Base64）
│                       #   • 錯誤重試邏輯

│                       #   • AGENTS 登錄表（名稱 + prompt）
│
├── pipeline.py         # MVPPipeline — 三步驟核心協調器
│                       #   • Step 1：呼叫 Visual Observer
│                       #   • Step 2：ThreadPool 並行呼叫 8 Agents

```

**三層架構圖**
```
User CLI (run.py)
      │
      ▼
MVPPipeline (pipeline.py)
  ├─ Step 1: call_visual_observer()
  │           └─ client.complete(STEP1_SYSTEM, images)
  │
  ├─ Step 2: call_agents_parallel()
  │           └─ ThreadPool.map(
  │                agent_task,
```

## Prompt 設計深度解析

### Step 1 Prompt 架構

**STEP1_SYSTEM**
```
角色: 「工程圖面純觀察者」（非製程分類器）
輸入:
  • 父圖 + 子視圖（全部一次送入，無順序要求）
  • 多視角聚焦於「同一零件」
輸出:
  • 5 段固定結構，繁體中文
  • 字數控制 150~250
  • 防幻覺規則：模糊處寫「疑似X，待確認」
結束: 無preamble，直接5段
```

**5 段結構詳解**
```
1️⃣ 材料/表面標註 (10~30字)
   ├─ 材質識別 (如「SUS304」「鋁板」)
   ├─ 表面符號 (如毛面、拋光符)
   ├─ 塗裝標示 (如「RAL 9003 white」)
   └─ 防烤/遮蔽 (如「此面不烤漆」)

2️⃣ 幾何特徵 (30~60字)
   ├─ 折彎 (數量、位置、角度)
   ├─ 孔 (分布、規格M3/M4、沉台/沉頭)
   ├─ 切口/邊界
   └─ 特殊形狀 (U/T/L/圓管)

3️⃣ 焊接/接合 (20~40字)
   ├─ 焊接符號 (位置+類型)
   ├─ 點焊標記
   ├─ 鉚合/螺帽
   └─ 組立關係

4️⃣ 文字標註與備註 (30~50字)
   ├─ 中英文備註
   ├─ 公差標示
   ├─ 客戶規格
   └─ 特殊加工指示

5️⃣ 整體判斷 (20~40字)
   ├─ 零件類型 (單件/組合/管件)
   ├─ 複雜度 (簡單/中等/複雜)
   └─ 工序預感 (無需命名，只說涉及多工序)
```

### Step 2 Prompt 架構（8 Agents）

**通用 AGENT_X_SYSTEM 結構**
```
1️⃣ 角色定位
   • 製程分類器 (限定範圍，只看自己的代碼)
   • 接收 Step1 描述 + 原始圖面

2️⃣ 信心度評分規則注入
   • 共通規則 (_CONF_RULES) 前綴
   • 強制禁止整數分數 (0.5/0.7/0.9)
   • 分數精確度決策邏輯

3️⃣ 製程代碼清單
   • 只列本 Agent 負責的代碼
   • 每個代碼的觸發條件詳寫
   • 異常狀況說明 (人工加註、score上限)

4️⃣ 互斥規則 (若有)
   • 明確列出「不能同時 APPLY」的配對
   • 優先級邏輯

5️⃣ 依賴規則 (若有)
   • 明確列出「自動觸發」的配對
   • Score 計算方式

6️⃣ 任務順序
   • Step 1: 視覺檢查圖面
   • Step 2: 交叉驗證 Step1 文字
   • Step 3: 逐一決策 APPLY/SKIP
   • Step 4: 強制互斥/依賴規則
   • Step 5: 分配信心度
   • Step 6: 如發現衝突，標註「圖面修正：[說明]」

7️⃣ 輸出規則
   • 只輸出 APPLY 的行
   • 格式嚴格：[代號] [名稱] | [分數] | 依據：[證據]
   • 若無 → 「此類別無對應製程」
   • 無preamble
```

**範例：Agent A 的製程列表結構**
```
Process list (ONLY these codes are valid output):
- C01 單機切割
  └─ 觸發：基本切割製程；若圖面/描述確認有 C05，則 C01 SKIP
  └─ Score：0.85~0.95（直接標示）

- C03 複合機
  └─ 觸發：任一視角可見架橋結構、通風孔陣列 OR 材質標示PP瓦楞板
  └─ Score：0.70~0.80

- C04 M2048
  └─ 觸發：排版決定分攤，通常圖面無法直接判斷
  └─ Score：上限0.55（推測性）

- C05 M3048（中心沖）
  └─ 觸發：圖面/備註有「抽牙M3/M4/M5」或「中心沖」文字 OR 幾何判斷需要
  └─ Score：0.85~0.95（直接標示）

- K01 燕巢切削
  └─ 觸發：任一視角可見沉頭孔幾何 OR 孔公差極小 OR 特殊幾何雷射無法成形
  └─ Score：0.75~0.85

- C01 and C05 are mutually exclusive — if C05 is APPLY (score ≥ 0.70),

```

### Step 3 Prompt 架構

**STEP3_SYSTEM 五大章節**

**§1 合併規則**
```
input: 8 個 Agent 的所有輸出行

邏輯:
  IF score ≥ 0.70
    → 無條件納入主表
  ELSE IF score 0.50~0.69
    → 納入，除非同類別有 ≥0.70 直接矛盾
  ELSE IF score 0.30~0.49
    → 僅當業務規則觸發時納入
  ELSE (score < 0.30)
    → 移至待人工確認
  
  IF 標有⚠️人工加註
    → 無論分數，永不自動納入
    → 必移至待人工確認
    → 標記「需業務/現場確認後加入」

去重：
  IF 重複製程
    → 保留最高分
    → 合併所有依據成單一行
```

**§2 信心度重算**
```
重算邏輯:
  base_score = max(各Agent報告分數)
  
  correction = 0
  IF 證據同時出現在「圖面」+「Step1文字」
    correction += 0.05  // 雙重確認
  IF 證據只在「Step1文字」無圖面確認
    correction -= 0.05  // 削弱信心
  
  final_score = clamp(base_score + correction, 0.10, 1.00)
  final_score = round(final_score, 2)  // 2位小數

例:
  • Base 0.75 + 圖面確認 → 0.80
  • Base 0.75 − 描述only → 0.70
  • Base 0.30 − 描述only → 0.10 (下限)
```

**§3 業務規則（6 條，自動注入 0.95）**
```
Rule 1 — 除焦洗淨
  IF F01 score ≥0.70 
     AND 材質 ∈ {白鐵,304,2B,316,不鏽鋼}
     AND F11 NOT in included_list
  THEN ADD H01 (0.95)

Rule 2 — 成品全檢2
  IF F01≥0.70 OR F11≥0.70 OR F25≥0.70
  THEN ADD I02 (0.95)

Rule 3 — 防烤遮蔽升級
  IF F11≥0.70 AND Q07 ∃ (any score)
  THEN Q07 = max(Q07_original_score, 0.82)

Rule 4 — 雷雕排序
  IF O02≥0.70
  THEN MARK O02 「排序：E01之後、D01之前」

Rule 5 — 去毛邊2
  IF (D01 OR D04)≥0.70 AND 板厚≥2.0T
  THEN ADD E02 (0.75)

Rule 6 — H01排除
  IF F11≥0.70
  THEN REMOVE H01 (即使之前APPLY)
```

**§4 固定基礎**
```
自動加入（system決定，不列主表）:
  B01 繪圖者
  B02 排版
  C01 單機切割 (exception: C05≥0.70時移除)
  E01 去毛邊
  I01 成品全檢
  H02 部品包裝
  J01 燕巢倉庫

註腳：
  「基本流程（B01/B02/C01/E01/I01/H02/J01）自動加入，不列於上表。」
  「若 C05 M3048 score ≥0.70，則 C01 從基本流程移除。」
```

**§5 輸出格式**
```
【主表】score ≥ 0.50，代碼排序 B→C→D→E→F→H→I→O→Q→K→J
| 製程編號 | 製程名稱 | 最終信心度 | 判斷依據摘要 |
|---------|---------|-----------|------------|
| D01     | 折彎    | 0.85      | 側視圖/等角圖明確90°折彎 |
| ...     | ...     | ...       | ... |

【待人工確認】0.10~0.49 + 全⚠️項
| 製程編號 | 製程名稱 | 信心度 | 原因 |
|---------|---------|--------|------|
| F10     | 植焊螺絲 | 0.35   | ⚠️ 人工加註，待業務確認 |
| ...     | ...     | ...    | ... |

【頁尾】
基本流程（B01/B02/C01/E01/I01/H02/J01）自動加入，不列於上表。
⚠️ 人工加註項目需業務或現場確認後方可加入製程。
```

## 已知狀況與限制

| 項目 | 說明 |
|------|------|
| Agent C 逾時 | Step2 並行時，後進入 queue 的 Agent 可能超過 timeout (300s)，已知問題 |
| 模型名稱顯示 | 輸出 header 的 Model 名稱讀自設定檔預設值，不代表 LM Studio 實際載入的模型 |
| 無 BOM 注入 | MVP 階段不注入 BOM System 詞彙，純圖面觀察，後續可依需求加入 |
| 父圖來源 | 一律使用**人類未加註** PDF 轉換 (200 DPI)，確保 VLM 不受人工提示影響 |
