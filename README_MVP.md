# MVP — Multi-Agent VLM 製程分類系統

> **Branch:** `MVP`  
> **狀態:** Proof-of-Concept（概念驗證）  
> **目標:** 驗證「三步驟多 Agent 串流」是否能從工程圖面自動輸出正確製程清單

---

## 架構總覽

```
INPUT: 父圖 (PDF → 影像) + 子圖 3~4 張 (JPG)
         │
         ▼
┌─────────────────────────────────────┐
│  Step 1  │  視覺觀察 Agent  (1 call) │
│          │  描述幾何/材料/焊接/文字   │
└────────────────┬────────────────────┘
                 │ 自然語言描述 (繁中，150~250字)
                 ▼
┌─────────────────────────────────────────────────────────┐
│  Step 2  │  8 個並行分類 Agent  (8 calls, ThreadPool)   │
│  Agent A │ 切割/成形   C01 C03 C04 C05 K01              │
│  Agent B │ 折彎/植件   D01 D04 D06 D07 D09 D10          │
│  Agent C │ 去毛邊/整平 E01 E02 E04 E08 E11 F22          │
│  Agent D │ 焊接類      F01 F03 F05 F06 F09~F27          │
│  Agent E │ 表面處理    F11 F17 H01 H04 H06 H12~Q07      │
│  Agent F │ 包裝/物流   H02 H03 H08 H10 H28 O12          │
│  Agent G │ 品檢        I01~I22                           │
│  Agent H │ 組裝/其他   Q01 Q08 Q09 Q11 O02 O04 F12…     │
└────────────────┬────────────────────────────────────────┘
                 │ 各 Agent 輸出：製程代碼 | 信心度 | 依據
                 ▼
┌─────────────────────────────────────┐
│  Step 3  │  彙整 Agent  (1 call)    │
│          │  合併去重 + 業務規則       │
│          │  → 最終製程表             │
└─────────────────────────────────────┘

每個 family 共 10 次 VLM calls (1+8+1)
```

## Step 1 Prompt 設計

**System Prompt 核心原則：**
- Agent 角色：工程圖面純觀察者，**不命名製程、不給建議**
- 輸入：父圖 + 最多 4 張子視圖（正/俯/側/等角），全部一次送入
- 輸出：繁體中文，固定 5 段結構，150~250 字

**5 段輸出結構：**
```
1. 材料/表面標註  — 材質文字、表面符號、塗裝色號、防烤標記
2. 幾何特徵      — 折彎線、孔位、螺紋孔、沉頭孔、切口
3. 焊接/接合特徵 — 焊接符號、點焊、鉚合、組立關係
4. 文字標註與備註 — 備註文字、公差要求、客戶規格
5. 整體判斷      — 零件類型（單件/組合件/管件）+ 複雜度
```

**防幻覺規則：** 若特徵模糊則寫「疑似[特徵]，待確認」，禁止自行發明不可見內容。

## Step 2 Prompt 設計（8 Agents 共通）

**每個 Agent 共享的設計原則：**

1. **範圍隔離** — 每個 Agent 只看自己類別的製程代碼，禁止輸出範圍外的代碼
2. **雙輸入** — 同時接收 Step1 文字描述 **和** 原始圖面影像；圖面優先（圖面 vs 描述衝突時以圖面為準）
3. **多視角規則** — 任意單一視角看到特徵即可觸發，不需全部視角一致
4. **信心度評分（0.00~1.00）：**

| 分數區間 | 意義 |
|---------|------|
| 0.90–1.00 | 圖面明確可見（文字完全吻合或符號清晰） |
| 0.70–0.85 | 幾何或材料強烈暗示（無直接標示但高度確定） |
| 0.50–0.65 | 合理推測（無直接證據，依零件複雜度判斷） |
| 0.30–0.45 | 間接推測（僅憑間接線索） |
| 0.10–0.25 | 極低可能（僅供人工複核標記） |

> **強制規則：** 禁止輸出整數信心度（0.5 / 0.7 / 0.9），必須強制精確區分（0.55 vs 0.65 是不同判斷）

5. **人工加註項目** — F10 / F16 / F25 / I14 / O14 等，VLM 不得主動觸發，信心度上限 0.35，強制移至「待人工確認」

6. **互斥與依賴規則（各 Agent 各異）：**
   - `C01` vs `C05` 互斥（C05 ≥ 0.70 時 C01 SKIP）
   - `D04` vs `D07` 互斥（折彎+植件 vs 明確植件先行順序）
   - `F14` 依賴 `F01`（有焊接必有焊接研磨）
   - `H01` 遇到 `F11` 時 SKIP（烤漆表處不需除焦）
   - 等…

**輸出格式（每行一條製程）：**
```
[製程編號] [製程名稱] | [0.00] | 依據：[具體觀察到的特徵或文字]
```

## Step 3 Prompt 設計（彙整 Agent）

**五大處理章節：**

**§1 合併規則**
- score ≥ 0.70 → 無條件納入
- score 0.50~0.69 → 納入（除非被同類別 ≥ 0.70 項目直接矛盾）
- score 0.30~0.49 → 僅當業務規則強制時納入
- score < 0.30 → 丟棄，移至「待人工確認」
- ⚠️ 人工加註項目 → 永遠不自動納入，移至「待人工確認」

**§2 分數重算**
- 基底 = 各 Agent 最高分
- +0.05 若圖面與描述雙重確認
- −0.05 若僅描述提到但圖面無確認
- 上限 1.00，下限 0.10，四捨五入至 2 位

**§3 業務規則（自動觸發）**

| 規則 | 觸發條件 | 動作 |
|------|---------|------|
| Rule 1 除焦洗淨 | F01焊接≥0.70 + 白鐵/304/不鏽鋼材質 + 無F11烤漆 | 新增 H01 (0.95) |
| Rule 2 成品全檢2 | F01或F11或F25任一≥0.70 | 新增 I02 (0.95) |
| Rule 3 防烤遮蔽升級 | F11≥0.70 且 Q07任意存在 | Q07升至 max(原分, 0.82) |
| Rule 4 雷雕排序 | O02≥0.70 | 標註「E01後、D01前」 |
| Rule 5 去毛邊2 | D01或D04≥0.70 且 板厚≥2.0T | 新增 E02 (0.75) |
| Rule 6 H01排除 | F11≥0.70 | 移除 H01 |

**§4 固定基本流程**（不列入主表，由系統自動加入）
```
B01 繪圖者 / B02 排版 / C01 單機切割 / E01 去毛邊 /
I01 成品全檢 / H02 部品包裝 / J01 燕巢倉庫
```
> 例外：若 C05 M3048 ≥ 0.70，則 C01 從基本流程移除

**§5 最終輸出格式**
```
主表（score ≥ 0.50，依代碼排序 B→C→D→E→F→H→I→O→Q→K→J）：
| 製程編號 | 製程名稱 | 最終信心度 | 判斷依據摘要 |

待人工確認（score 0.10~0.49 + 所有⚠️人工加註項目）：
| 製程編號 | 製程名稱 | 信心度 | 原因 |
```

## 執行方式

```bash
# 指定單一 family 測試
python -m mvp.run --family 5010-586800-11A

# 多個 family
python -m mvp.run --family 108-001416-13A 161-01757-00_A

# 全部 7 個 family
python -m mvp.run

# 跳過父圖（純子視圖模式）
python -m mvp.run --family 5010-586800-11A --no-parent

# 調整 Step2 並行數（預設 4）
python -m mvp.run --workers 2

# 列出所有可用 family
python -m mvp.run --list
```

輸出儲存至：`test_output/mvp_result_<timestamp>.txt`

## 已知狀況與限制

| 項目 | 說明 |
|------|------|
| Agent C 逾時 | Step2 並行時，後進入 queue 的 Agent 可能超過 timeout (300s)，已知問題 |
| 模型名稱顯示 | 輸出 header 的 Model 名稱讀自設定檔預設值，不代表 LM Studio 實際載入的模型 |
| 無 BOM 注入 | MVP 階段不注入 BOM System 詞彙，純圖面觀察，後續可依需求加入 |
| 父圖來源 | 一律使用**人類未加註** PDF 轉換 (200 DPI)，確保 VLM 不受人工提示影響 |
